# 🧠 WEBSITE DESIGN WORKSHOP: Health Resilience Mapping Project

## Executive Summary
A day-long expert workshop with 15 team members revealed that a single website cannot serve all audiences without harm. The breakthrough solution: three synchronized but separate web experiences for communities, researchers, and policy makers, prioritizing dignity while maintaining rigor.

## 🎯 WORKSHOP ROUNDS & KEY INSIGHTS

### Round 1: Initial Visions
**Central Tension**: Map-first (journalists/researchers) vs. Story-first (community/advocates)

**Key Quotes**:
- Maria: "The homepage cannot be a map with dots. It needs to be faces, stories, dignity."
- Dr. Chen: "The map is misleading without confidence intervals."
- Marcus: "First thing people want to know: 'Is this about me?'"
- Mike: "This sounds like 'We studied poor people and some aren't dying as fast as expected! 🎉'"

**Breakthrough**: Jasmine's three-door concept - EXPLORE, UNDERSTAND, ACT

---

### Round 2: The Homepage Battle
**Resolution**: Question-based entry instead of data visualization

**Rejected Concepts**:
- Map with resilience scores (too clinical)
- Statistics dashboard (too academic)
- "Is my community in this study?" (too experimental)

**Accepted Framing**: 
- "Find your community's story"
- "The Mystery of America's Healthiest Food Deserts"
- Acknowledgment of absurdity upfront

---

### Round 3: The Map Controversy
**Technical Innovation**: Progressive disclosure mapping
- Starts grayscale, reveals color on zoom
- Hover for confidence intervals
- Click for stories
- "Remove my community" option

**Visual Elements Consensus**:
1. Resilience score (color)
2. Confidence interval (opacity)
3. Population size (border thickness)
4. Community annotations (pins)

---

### Round 4: The Story Layer
**Three Story Types**:
1. **Data Stories**: Auto-generated narratives per tract
2. **Human Stories**: Video testimonials (no inspiration porn)
3. **Historical Stories**: How places got this way

**Critical Quote** (Marcus): "My neighborhood isn't 'resilient.' We're exhausted."

---

### Round 5: The Defense Layer
**Every Page Warning Evolution**:
- First draft: Academic disclaimer (rejected - too professorial)
- Mike's version: "If communities are surviving without grocery stores, imagine how they'd thrive WITH them." (accepted)
- Technical solution: Watermarks on all screenshots

---

### Round 6: The Search Experience
**User Flow Design**:
```
Input: "Birmingham, Alabama"
Output: Contextual choices, not raw data
- Specific neighborhood details
- City's food story
- Comparisons
- "Tell us what we got wrong"
```

**Innovation**: Swipe-through neighborhoods (mobile) like social media stories

---

### Round 7: The Researcher Portal
**Requirements Defined**:
- Raw data in multiple formats
- Reproducible analysis scripts
- Version control/changelog
- Community impact pledge before download
- Mike's addition: "I will not be an asshole" checkbox

---

### Round 8: Mobile-First Reality
**Progressive Web App Consensus**:
- Works offline after first visit
- No app store needed
- Location-based entry
- Share via WhatsApp/SMS
- Works on $50 Android phones

---

### Round 9: The Controversy Section
**Radical Transparency**:
- Prominent "Criticisms" page
- Known limitations listed first
- Links to rebuttals
- Community challenges welcomed
- Dr. Chen: "Career suicide but necessary"

---

### Round 10: Unexpected Features
**Community-Driven Additions**:
- Community Assets Map (churches, mutual aid)
- Recipe section for food desert cooking
- TikTok integration for food stories
- Audio stories for non-readers
- "Political Misuse Hall of Shame"

## 💡 THE BREAKTHROUGH MOMENT

### Three Synchronized Sites Solution

Jasmine's revolutionary proposal, immediately accepted by team:

**Instead of one site trying to serve everyone, create three synchronized experiences:**

1. **Community-Focused Site**
2. **Research-Focused Site**  
3. **Policy-Focused Site**

This prevents audience collision while maintaining coherence.

## 🏗️ FINAL CONSENSUS DESIGN

### Overall Architecture

```yaml
MAIN PORTAL: [Domain TBD - see alternatives below]
  
Landing Experience:
  - Question-based entry (not map-first)
  - Three pathways clearly marked
  - Immediate value proposition for each audience
  - Trust indicators visible
  - Update status prominent
  - Language selector
```

### Core Features

#### 1. Story-Driven Map
- Communities plotted with stories, not just data points
- Progressive zoom (grayscale → color)
- Confidence visualization via opacity
- Multiple context layers
- Community-added annotations
- Historical overlays

#### 2. Human-Centered Search
- Address/ZIP code (not census tract)
- City/neighborhood name
- "Near me" GPS option
- Community-known names
- Voice search option
- Predictive suggestions

#### 3. Defensive Design Elements
- Warnings embedded in interface
- Context required for access
- Misuse tracking system
- Community veto mechanism
- Screenshot watermarking
- Citation tracking

#### 4. Multi-Modal Content
- Text at multiple reading levels (6th grade + academic)
- Video stories (with captions)
- Audio/podcast format
- Interactive infographics
- Raw data downloads
- Print-friendly versions

#### 5. Community Engagement Tools
- "Correct this data" form
- "Add community context" feature
- "Share your story" portal
- "Report misuse" system
- Community annotation system
- Feedback dashboard

### Technical Specifications

```yaml
Architecture:
  - Progressive Web App (PWA)
  - Offline-first design
  - CDN distributed globally
  - RESTful + GraphQL APIs
  - Git-based version control
  - Privacy-preserving analytics
  - Server-side rendering for SEO

Performance Targets:
  - First contentful paint: <1.5s
  - Time to interactive: <3s
  - Lighthouse score: 95+
  - Works on 3G networks
  - <500KB initial bundle

Accessibility Requirements:
  - WCAG AAA compliance
  - Screen reader optimized
  - Keyboard navigation complete
  - Color blind safe palettes
  - Cognitive accessibility considered
  - Multiple language support
```

### Trust Building Features

```yaml
Transparency Elements:
  - Team photos and bios
  - Funding sources listed
  - Conflict of interest statements
  - Update/correction log
  - Community board members visible
  - Peer review status
  - Contact information prominent

Community Protections:
  - Opt-out mechanisms
  - Privacy policy clear
  - Data use agreements
  - Community benefit sharing
  - Local organization partnerships
  - Feedback response timeline
```

## ⚠️ CRITICAL DECISIONS MADE

### What We're NOT Building
- ❌ Single monolithic site for all audiences
- ❌ Map-first experience
- ❌ Academic-only interface
- ❌ Static data publication
- ❌ English-only content
- ❌ Desktop-first design
- ❌ Closed-source platform

### What We ARE Building
- ✅ Three synchronized experiences
- ✅ Story-driven narrative
- ✅ Community-controlled elements
- ✅ Living, updatable system
- ✅ Multilingual support
- ✅ Mobile-first approach
- ✅ Open-source components

### Non-Negotiable Principles
1. **Community dignity over data display**
2. **Accessibility over aesthetics**
3. **Protection over transparency**
4. **Stories alongside statistics**
5. **Humility in claims**
6. **Rapid response to harm**
7. **Community veto power**

## 🎯 FINAL WORKSHOP CONSENSUS

**The Big Idea**: This isn't just a website—it's a new model for presenting controversial research about vulnerable communities that prioritizes dignity while maintaining rigor.

**The Innovation**: Three synchronized sites prevent audience collision while enabling each group to get what they need without harming others.

**The Promise**: Build with communities, not about them. Measure success by harm prevented, not traffic generated.

**The Commitment**: Launch only with community blessing, iterate based on feedback, and maintain the site as a living system responsive to community needs.
