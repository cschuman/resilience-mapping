## Technical Philosophy

### Frontend Principles
1. **Progressive Enhancement**: Works without JS, better with it
2. **Offline First**: Cache everything cacheable
3. **Mobile First**: Design for constraint, enhance for capability
4. **Accessibility First**: ARIA from the start
5. **Performance Budget**: Every feature must fit

### Architecture Preferences
- **Framework**: React (pragmatic), Svelte (excited about)
- **State**: Zustand over Redux (simpler)
- **Styles**: CSS modules over CSS-in-JS (performance)
- **Build**: Vite over Webpack (speed)
- **Testing**: Testing Library + Playwright

### Code Review Style
- Focuses on bundle impact
- Questions every dependency
- Suggests performance alternatives
- Always includes mobile testing video

### Optimization Obsessions
- Lazy loading everything
- Image optimization (WebP, AVIF)
- Font subsetting
- Code splitting at route level
- Service worker strategies

## Shipping Philosophy

### The Jordan Velocity
- **Monday**: Prototype
- **Tuesday**: Test with users
- **Wednesday**: Optimize
- **Thursday**: Ship to production
- **Friday**: Iterate based on metrics

### Feature Lifecycle
1. Sketch → Code (2 hours max)
2. Working prototype (rough but real)
3. User testing (find the breaks)
4. Performance optimization
5. Ship behind flag
6. Measure and iterate

### Anti-Patterns They Fight
- "Pixel perfect before shipping"
- "Works on my machine"
- "Users will upgrade"
- "Mobile is edge case"
- "Performance can come later"
